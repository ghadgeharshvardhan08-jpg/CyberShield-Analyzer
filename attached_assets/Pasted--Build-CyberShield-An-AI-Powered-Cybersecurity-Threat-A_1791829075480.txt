# Build CyberShield — An AI-Powered Cybersecurity Threat Analysis Platform

Act as a senior full-stack developer, cybersecurity engineer, UI/UX designer, and software architect. Build a complete, professional, production-minded web application called **CyberShield** that I can showcase on my resume, GitHub, internship applications, and future Master's applications in Computer Science or Cybersecurity.

## 1. Project objective

Create an educational cybersecurity platform that helps users identify suspicious URLs, understand phishing risks, analyze security indicators, and learn cybersecurity best practices.

This must be a functional software project, not just a static UI prototype.

## 2. Technology stack

Use the following technologies:

- Frontend: React with TypeScript and Vite.
- Styling: Tailwind CSS with a polished, responsive design.
- UI components: Accessible, reusable components with Lucide icons.
- Backend: Python with FastAPI.
- Database: PostgreSQL for persistent data, with SQLite as an optional local-development fallback.
- Data visualization: Recharts.
- Testing: Pytest for the backend and Vitest for frontend components.
- Documentation: Markdown, API documentation, and a complete README.
- Deployment: Provide deployment instructions for a suitable frontend host and a Python backend host.

Use stable, compatible dependencies and provide all necessary configuration files.

## 3. Core features

### A. URL threat analyzer
- Allow users to submit a URL for analysis.
- Validate URL format and normalize input safely.
- Detect suspicious indicators, including misleading domain patterns, unusual URL encoding, IP-address-based hosts, excessive subdomains, suspicious keywords, and non-HTTPS connections.
- Distinguish between detected indicators and confirmed threats.
- Produce a transparent risk score from 0 to 100 using documented rules.
- Show a risk category: Low, Medium, High, or Critical.
- Explain every finding in simple language.
- Never claim that a URL is completely safe just because no indicators were detected.
- Do not automatically open, crawl, or visit submitted URLs.

### B. Security dashboard
- Display total analyses, risk-category distribution, recent scans, and trends over time.
- Include interactive charts, summary cards, filters, and searchable analysis history.
- Use genuine stored application data rather than fabricated statistics.
- Show a helpful empty state when there is no data.

### C. Security report generator
- Generate downloadable PDF reports.
- Include the submitted URL, timestamp, detected indicators, risk score, explanations, and recommendations.
- Clearly label the results as an automated preliminary assessment, not a guarantee or a professional security audit.

### D. Cybersecurity learning center
- Create learning modules covering phishing, social engineering, password security, ransomware, malware, and safe browsing.
- Add multiple-choice quizzes with explanations.
- Track completed lessons and quiz scores.
- Use original educational content and practical examples.

### E. User accounts and history
- Implement secure registration, login, logout, and password hashing.
- Keep each user's scan history private.
- Validate and authorize all API requests.
- Use environment variables for secrets.
- Include rate limiting and sensible request-size limits.

### F. Security and privacy
- Protect against common web vulnerabilities, including injection, cross-site scripting, broken access control, and insecure authentication.
- Prevent server-side request forgery by never fetching arbitrary submitted URLs.
- Avoid storing sensitive personal information unnecessarily.
- Add clear privacy notices and safe error messages.
- Never expose API keys, database credentials, or secret configuration values in frontend code.
- Do not add offensive scanning, exploitation, or unauthorized-access functionality.
